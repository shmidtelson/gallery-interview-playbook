**Документ:** внутренний, по найму

**Роль:** full-stack разработчик (PHP 8 / Symfony, React), продукт галерей для фотографов  
**Формат:** техническое интервью, ~47 минут  
**Источник:** расшифровка `Video_2026-08-31_17-08-52.srt`  
**Рекомендация:** отказ

## Решение

Кандидата на эту позицию не нанимать.

Роль предполагает коммерческий Symfony, работу с React (в том числе публичные галереи) и самостоятельное ведение задач напрямую у фаундера, без спринтов и ежедневных статусов. По итогам разговора кандидат — backend-разработчик на Laravel в модели аутстаффа. Коммерческого опыта Symfony нет. React в текущей работе не использует. Подход к типовой задаче продукта (второй регион и отключение функций) не покрывает хранение файлов, переключение и откат.

Нанимать его как единственного full-stack на этот продукт — неоправданный риск по срокам и качеству.

## Риски, если нанять

1. **Срок выхода.** Первые недели уйдут на Symfony и чужую схему, а не на поставку. На позиции один исполнитель — простой дороже, чем в команде.
2. **Регрессии в галереях.** Нет подтверждённого опыта с клиентским доступом по ссылке, превью, большими альбомами.
3. **Регион и платежи.** Отключение магазина через UI без жёсткого запрета на backend даёт риск принять оплату там, где функция должна быть выключена.
4. **Управление.** Привычный контур — daily и постановка от менеджера. Вечерняя постановка от фаундера без ритуалов команды с ним не совпадает.
5. **Качество при AI.** Без второго ревьюера поверхностная проверка агентского кода повышает вероятность скрытых дефектов в платежах и доступе к чужим галереям.

## Что в профиле сильное

- Честно обозначил отсутствие Symfony и слабость фронтенда — нет завышения резюме по главному стеку.
- Платёжный сценарий Т-Банка описал по шагам (создание ссылки, редирект, возврат, фиксация платежа).
- Для нескольких платёжных систем предлагает коннектор, а не ветвление по стране в каждом обработчике.
- Понимает, что результат модели нужно проверять; приводит примеры ошибок в чужом коде (лишние запросы).

Этого достаточно для mid-level backend на Laravel в команде. Этого недостаточно для указанной роли.

## Альтернатива

На эту вакансию — отказ.

Рассматривать как узкий backend (платежи, флаги, интеграции) имеет смысл только если роль будет переписана и появится отдельный человек на Symfony/React. Проверка тогда одна: выключить магазин на API и провести тестовый платёж и вебхук без агента, по существующей схеме. Пока роль не менялась — этот путь не предлагается.
